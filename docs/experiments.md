# Experiments and usage

[Project overview](../README.md)

Commands below run from the repository root.

## Included data

Both cases generate paired two-dimensional endpoints from analytic couplings.
The released NumPy archives contain the samples and trajectories used in the
figures. Per-sample metrics are stored as CSV files beside each archive.

| Case | Archive | Endpoint pairs | Trajectory shape |
| --- | --- | ---: | --- |
| Smooth closed coupling | [closed_coupling_data.npz](../data/case1_smooth_closed/closed_coupling_data.npz) | 1,024 | 61 states × 1,024 pairs × 2 coordinates |
| Curved multi-branch coupling | [toy_case2_checkpoint_trajectories.npz](../data/case2_curved_multibranch/toy_case2_checkpoint_trajectories.npz) | 4,096 | 21 states × 4,096 pairs × 2 coordinates |

Case I includes trajectories for the three-head model with and without
correction. The Case II archive includes the two three-head trajectories;
its [per-sample table](../data/case2_curved_multibranch/per_sample_metrics.csv)
also contains the single-head metrics.

To inspect the arrays:

```python
import numpy as np

with np.load("data/case1_smooth_closed/closed_coupling_data.npz") as data:
    print(data.files)
    print(data["trajectory_triad"].shape)
    print(data["trajectory_corrected"].shape)
```

## Case I: smooth closed coupling

The target and terminal curves share a latent angle. Sampling compares the same
130,566-parameter three-head model before and after correction.

| Setting | Value |
| --- | --- |
| Training seed | 1234 |
| Training updates | 20,000 |
| Evaluation seed | 20261002 |
| Endpoint pairs | 1,024 |
| Reverse updates | 60 |
| Maximum correction strength | 0.12 |
| Network calls, without / with correction | 60 / 120 |

| Metric | Without correction | With correction |
| --- | ---: | ---: |
| Mean endpoint distance | 0.01359 | 0.00925 |
| Mean path-support distance | 0.03416 | 0.01217 |
| Coordinate-wise endpoint RMSE | 0.01075 | 0.00712 |

Endpoint distance is the Euclidean distance between a predicted endpoint and
its paired target, averaged over samples. A distance of 0.01 means a separation
of 0.01 coordinate units. Path-support distance averages the nearest-support
distance across the 61 trajectory states and then across samples.
Coordinate-wise RMSE takes the square root after averaging squared errors
over both spatial coordinates and samples.

The [original model and training source](../code/case1_smooth_closed/original_closed_coupling.py)
and [figure export source](../code/case1_smooth_closed/export_closed_coupling.py)
are included. The export script retains its original execution paths and
hostname check. The released arrays support data inspection directly.

## Case II: curved multi-branch coupling

The evaluation uses curvature `kappa=0.6`, 4,096 endpoint pairs, 20 reverse
updates, and a maximum correction strength of 0.02 with a sine-squared schedule.
Training uses seed 123; evaluation uses seed 2026.

The noise scale at bridge time `t` is
`s(t) = 0.02 + 0.70 * sqrt(t * (1 - t))`.

| Model | Parameters | Training updates | Batch size |
| --- | ---: | ---: | ---: |
| Single head | 112,706 | 50,000 | 1,024 |
| Three head | 301,062 | 30,000 | 256 |

Both models use AdamW, learning rate 0.0002, weight decay 0, gradient clipping
at 1, hidden width 192, and depth 3.

| Method | Endpoint RMSE | Mean endpoint distance | Mean path-support distance |
| --- | ---: | ---: | ---: |
| Single head | 0.09143 | 0.02489 | 0.08059 |
| TriadBridge | 0.08623 | 0.01901 | 0.07382 |
| Triad + projection | 0.08560 | 0.01981 | 0.06649 |

Here endpoint RMSE is the square root of the mean squared Euclidean endpoint
distance. Case I's coordinate-wise RMSE additionally averages over its two
coordinates. The model configurations are
[single head](../configs/case2_single.json),
[three head](../configs/case2_triad.json), and
[evaluation](../configs/case2_evaluation.json).

## Training

The following commands specify the archived Case II model and optimization
settings. Synthetic training pairs are generated by the training script.

Single head:

```bash
python code/case2_curved_multibranch/train_curved_multibranch_toy_v2.py \
  --model_type single --outdir runs/case2_single --device cuda \
  --seed 123 --kappa 0.6 --sigma_min 0.02 --sigma_max 0.7 \
  --steps 50000 --batch_size 1024 --hidden 192 --depth 3 \
  --lr 2e-4 --weight_decay 0 --grad_clip 1.0 \
  --lambda_score 1.0 --lambda_endpoint 0.2
```

Three head:

```bash
python code/case2_curved_multibranch/train_curved_multibranch_toy_v2.py \
  --model_type bp --outdir runs/case2_triad --device cuda \
  --seed 123 --kappa 0.6 --sigma_min 0.02 --sigma_max 0.7 \
  --steps 30000 --batch_size 256 --hidden 192 --depth 3 \
  --lr 2e-4 --weight_decay 0 --grad_clip 1.0 \
  --lambda_score 1.0 --lambda_bridge 0.5 --lambda_transport 0.25 \
  --lambda_endpoint 5.0 --lambda_corr 1e-4
```

Each command writes `checkpoints/latest.pt`, numbered checkpoints,
`train_losses.csv`, and a `visuals/` directory under the requested output
directory. Checkpoint metadata includes the model arguments.

The release contains derived trajectory archives. Evaluation from model
weights uses the checkpoint files described in
[checkpoint storage](../checkpoints/README.md).
